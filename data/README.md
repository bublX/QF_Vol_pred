# Данные проекта

В Git храним исходный архив минутных цен и его описание. Распакованные CSV и результаты обработки создаются локально и исключены из Git.

```text
data/
  archives/1m_2014_2025/
    prices_1m_2014_2025.zip
  raw/1m_2014_2025/
    prices_1m_2014_2025.csv
  processed/
    <dataset>/
```

## Исходный набор

Архив содержит общую таблицу минутных цен закрытия десяти акций MOEX за 2014–2025 годы. Это цены `close`, а не полные свечи OHLCV. Значения отсутствующих наблюдений остаются пустыми; архив не заполняет их и не фильтрует выбросы.

В таблице 2 031 337 строк: столбец `date` и цены закрытия VTBR, SBER, LKOH, ROSN, NVTK, TATN, GAZP, GMKN, NLMK, MGNT. Фактический диапазон временных меток — с 2014-01-06 10:00:59 по 2025-12-30 23:49:59. Точный запрос и дата первоначальной выгрузки не сохранены.

## Подготовка после клонирования

После установки окружения (`uv sync --locked`) выполните из корня проекта:

```bash
uv run python main.py --config "configs/<experiment>.yaml" --stage prepare
```

Замените `<experiment>` именем своего YAML-файла из `configs/`.
Эксперимент наследует значения из `configs/default.yaml` и переопределяет
нужные параметры; конкретные имена конфигов и настройки выбирает разработчик.

`DatasetPreparer` извлекает CSV из `data.archive_path` в
`data.raw_dir`/`data.raw_file`. Имя выходного файла должно совпадать с именем CSV
в архиве. Если CSV уже существует, он проверяется и используется повторно.
Проверка включает заголовок, обязательные столбцы и наличие непустой строки
данных; она не проверяет корректность всех дат, цен и полноту истории.

Для ручной распаковки можно использовать PowerShell:

```powershell
Expand-Archive -LiteralPath "data/archives/1m_2014_2025/prices_1m_2014_2025.zip" -DestinationPath "data/raw/1m_2014_2025"
```

Если CSV уже распакован и готов к использованию, повторная распаковка не нужна.

Альтернатива ручной распаковки для Git Bash:

```bash
uv run python -m zipfile -e data/archives/1m_2014_2025/prices_1m_2014_2025.zip data/raw/1m_2014_2025
```

## Обработка

Повторное скачивание для комплектного набора не требуется. Выберите конфиг и выполните `process`, затем обучение:

```bash
uv run python main.py --config "configs/<experiment>.yaml" --stage process
uv run python main.py --config "configs/<experiment>.yaml"
```

| Параметр | Что определяет |
|---|---|
| `data.interval` | Длительность итогового бара в минутах |
| `processing.session_start` / `session_end` | Начало и конец учитываемой сессии |
| `processing.price_steps` | Обработка цен и параметры её шагов |
| `processing.returns` | Расчёт доходностей |
| `processing.steps` | Фильтры доходностей и их параметры |
| `processing.processed_dir` | Каталог производного набора данных |

Фактические настройки определяются слиянием `configs/default.yaml` и файла
эксперимента. Сессия включает начало и исключает конец; учитываются будние дни.
Параметр Хампеля `window_size` — полуширина окна в наблюдениях, а не в минутах.

В `processing.processed_dir` обработчик создаёт `RV/`, `rv_matrix.csv`,
`profit_matrix.csv` и `missing_days.csv`. Повторный `process` с тем же каталогом
перезаписывает его результаты. Используйте разные каталоги для разных интервалов
или вариантов обработки. При анализе в ноутбуке укажите путь к нужному набору.

Если несколько моделей используют одинаковые исходные данные и все параметры
обработки, им достаточно одного `process` и общего `processed_dir`.
Обучение каждой модели выполняется со своим конфигом; разные `output.name`
сохраняют таблицы результатов отдельно.

### Интервалы и обработчики

Для комплектного архива оставьте `data.source_interval: 1`. Параметр
`data.interval` задаёт длительность итогового бара в минутах: из минутных цен
можно получить, например, 3-, 5- или 15-минутные бары без нового скачивания.
Итоговый интервал должен быть не меньше исходного и кратен ему.

`BarAggregator` отсчитывает бары от `processing.session_start` и отбрасывает
последний неполный интервал сессии. Закрытие — последнее непустое значение цены
каждого тикера в баре. Метка времени — конец бара минус одна секунда.
`processing.min_bar_coverage` задаёт минимальную долю исходных свечей в баре;
даже при 0 требуется хотя бы одна свеча. Если покрытия недостаточно, цена
бара остаётся `NaN`.

Порядок дальнейшей обработки каждого тикера:

```text
Подготовка и сортировка → проверка покрытия дня → price_steps → returns → steps → удаление строк без close или returns → RV
```

`processing.min_day_coverage` задаёт долю итоговых баров с реальной ценой,
необходимую для отбора дня. Число ожидаемых баров зависит от сессии и интервала;
порог равен `max(2, ceil(expected_bars_per_day * min_day_coverage))`.
Покрытие проверяется до заполнения пропусков. `missing_days.csv` содержит
тикер, дату и число баров исключённого дня; дни без единой строки исходных
данных в отчёт не добавляются.

В `processing.price_steps` задаются шаги обработки цен, в `processing.returns` —
обязательный расчёт доходностей, в `processing.steps` — фильтры доходностей.
По умолчанию выполняются Хампель на `close`, заполнение цен внутри дня,
внутридневные лог-доходности, Хампель на `returns` и обрезка ±5%.
Заполнение не переносит цену между днями; начальные пропуски удаляются.
Ночной разрыв в доходности не входит.

`price_steps: []` и `steps: []` отключают соответствующие дополнительные шаги.
Списки в конфиге эксперимента заменяют стандартные целиком. После изменения
интервала, сессии или обработки заново выполните `process`, затем обучение.
Примеры YAML и добавление нового обработчика — в [основном README](../README.md#настройка-обработки-данных).

## Скачивание другого набора

Для нового скачивания остаётся этап `load`. Настройте тикеры, годы,
`source_interval`, `raw_dir` и `raw_file`; выбирайте отдельный путь, чтобы
сохранить комплектный исходник. При загрузке `source_interval` передаётся
как код интервала свечей MOEX ISS — биржа должна поддерживать этот интервал.
Для последующей агрегации он трактуется как длительность в минутах, поэтому
описанный процесс рассчитан на минутные исходные интервалы. `data.interval`
управляет только локальной агрегацией и не отправляется в запросе загрузки.

```bash
uv run python main.py --config "configs/<experiment>.yaml" --stage load
```

После скачивания выполните `process` и обучение с тем же конфигом.
